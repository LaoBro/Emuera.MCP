Problem. 9 个核心字段是进程级 static，lock + 断言式单赋值。EmueraConsole、Process、Session 全部穿墙读写 GlobalStatic.X。任何 C# 单元测试要么先完整初始化整条链（Config→Process→EmueraConsole），要么污染进程状态影响下一个测试。

Solution. 把 GlobalStatic 的 9 字段收敛为一个会话作用域实例，经构造注入。进程级 static 退化为单实例 holder（仅 Server/CLI 入口持有一次）。

  • leverage：一个 SessionContext 接口，N 个调用点不再读 static
  • locality：会话生命周期 bug 集中到一处，不再散落 4 模块
  • interface 是测试面：测试注入 fake SessionContext，无需 ERB/Config/字体
  • 解锁 EmueraConsole / Process / Session 的隔离单测

Problem. Config 是 659 行纯静态类，144 个 public static 成员。全仓 Config.FontName / Config.UseSaveFolder 散落调用。删除测试：删掉 Config，144 处调用全部塌缩到调用方 — 复杂度集中，证明它在赚钱。但它的 interface 与 implementation 几乎同宽（每个 static 属性就是一行 delegation），是教科书级 shallow module。

Solution. ConfigData 升为实例（已存在 925 行数据类，只需去掉 static），加载 emuera.config 后作为依赖注入。FontFactory / Process / EmueraConsole 接收 ConfigData 而非读 static。

  • depth：加载逻辑沉到实现，interface 只剩"取值"
  • locality：配置解析 bug 集中到 ConfigData 一处
  • leverage：一个 ConfigData 实例，N 个消费者，测试用 fake
  • Shared 债务清零（P2-6）的前提：static 去掉后 nullable 警告才可逐条修

Problem. ERB 引擎核心被塞进一个 partial 类：脚本执行、系统指令、状态管理、函数调用四职责混在 3636 行里。Process.Initialize 直接写 GlobalStatic.GameBaseData 等 9 字段 — 与候选 1 双向耦合。无法在测试里实例化 Process 而不拉起整个引擎。

Solution. 沿 ERB 生命周期（加载 / 求值 / 指令派发 / 状态）切 seam。Process 收敛为派发入口，partial 各自升为深模块，依赖经 SessionContext 注入而非 GlobalStatic。

  • locality：ERB 指令 bug 集中到 StatementDispatch，不再混在 1140 行 SystemProc
  • depth：Evaluator 的 interface 远小于当前 Process 的 17+ public 方法
  • 风险最高：引擎核心，回归面大；需 ADR 护航
  • 依赖候选 1（GlobalStatic 解除）先落地

Problem. CLI 的 TerminalRenderer 直接读 displayLineList（富：行/段/按钮/样式/坐标）；Web 只拿到 TurnRecord.ops[]（print/newline/clearline/clear/set_bg）。ButtonRef 只有 value 无几何，前端须重写 ButtonRegionTracker。无全屏路由，WS 晚加入者无回放。图像 PrintImg 退化为 node.ToString()。

Solution. 收敛为单一 DisplayState module：全量快照路由（首次/重连）+ 增量 ops + 按钮几何 + 资源引用。CLI 与 Web 同为 adapter。

  • leverage：一个接口，CLI/Web/测试三个 adapter
  • depth：渲染状态全部藏在实现后，前端不再重写终端逻辑
  • interface 是测试面：快照/增量可单测，无需真实游戏
  • 两个 adapter（CLI + Web）证明 seam 真实存在
⚠ 与 ADR-0003 的 v1 范围部分冲突 — 该 ADR 接受"晚加入者不回放历史"。但 Web 前端若无初始全屏状态根本无法渲染，摩擦真实。建议重开 ADR-0003 评估"v1 快照路由"是否纳入。

首推：候选 1 — GlobalStatic 进程级单例

Strong

它是用户四项关切的共同锁眼。GlobalStatic 解除前，C# 单元测试无法隔离（关切 1），Web 前端无法获得可测试的会话工厂（关切 3），Shared 重构（候选 2/3）因 static 双向耦合而无从下手（关切 4）。跨平台构建（关切 2）已基本就绪，但 Config/FontFactory 仍读 static — 解除 GlobalStatic 是它们可实例化的前提。

删除测试通过：删掉 GlobalStatic，9 字段复杂度会集中重现到 EmueraConsole / Process / Session 三处 — 它在赚钱，但当前以 static 形态赚钱，深化为实例后杠杆翻倍。候选 2（Config）是其自然后续，候选 3（Process）依赖它先落地，候选 4（Web seam）在其之上才能建可测试的会话工厂。
