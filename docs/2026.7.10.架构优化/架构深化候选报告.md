## 一、背景

用户担心现有架构不足以支撑接下来的开发任务（单测、跨平台构建、Web 前端）。本报告基于一次架构审查，识别 5 个深化候选——把 shallow module 收敛为 deep module，目标是 testability 与 AI-navigability。

**审查结论速览**：

| 关切 | 现状 | 阻塞点 |
|------|------|--------|
| 单元测试 | 仅 Python 端到端测试（spawn 二进制走 HTTP/JSONL），零 C# 单测 | GlobalStatic 进程级单例 + Config 静态类 |
| 跨平台构建 | 基本就绪（csproj 干净、System.Drawing 已移除、WinForms 代码 `#if !HEADLESS` 隔离） | Config/FontFactory 仍读 static，无法实例化验证 |
| Web 前端 | 协议层（TurnRecord v2 ops + /ws + /turn）已就位，但接缝过浅 | ops 是 displayLineList 的有损投影，无全屏路由/回放/按钮几何/图像 |
| Shared 臃肿 | Process 3636 行 god object、Config 659 行静态类、Image/PluginSystem 死代码 | static 双向耦合阻断重构 |

## 三、候选详情

### 候选 1 — GlobalStatic 进程级单例（单元测试的锁眼）

- **强度**：Strong
- **依赖类别**：in-process
- **文件**：
  - [Emuera.Headless/GlobalStatic.cs](file:///d:/LaoBro/Emuera.MCP/Emuera.Headless/GlobalStatic.cs)
  - [Emuera.Headless/UI/Game/EmueraConsole.cs](file:///d:/LaoBro/Emuera.MCP/Emuera.Headless/UI/Game/EmueraConsole.cs)
  - [Emuera.Headless/Shared/Runtime/Script/Process.cs](file:///d:/LaoBro/Emuera.MCP/Emuera.Headless/Shared/Runtime/Script/Process.cs)
  - [Emuera.Headless/Server/Session.cs](file:///d:/LaoBro/Emuera.MCP/Emuera.Headless/Server/Session.cs)

**Problem**：9 个核心字段是进程级 `static`，lock + 断言式单赋值。EmueraConsole、Process、Session 全部穿墙读写 `GlobalStatic.X`。任何 C# 单元测试要么先完整初始化整条链（Config→Process→EmueraConsole），要么污染进程状态影响下一个测试。

**Solution**：把 9 字段收敛为会话作用域实例，经构造注入。进程级 static 退化为单实例 holder（仅 Server/CLI 入口持有一次）。

**Benefits**：
- **leverage**：一个 SessionContext 接口，N 个调用点不再读 static
- **locality**：会话生命周期 bug 集中到一处，不再散落 4 模块
- **interface 是测试面**：测试注入 fake SessionContext，无需 ERB/Config/字体
- 解锁 EmueraConsole / Process / Session 的隔离单测

**删除测试**：✅ 通过 — 删掉 GlobalStatic，9 字段复杂度会集中重现到 EmueraConsole / Process / Session 三处，证明它在赚钱；当前以 static 形态赚钱，深化为实例后杠杆翻倍。

**Before/After**：
- Before：`GlobalStatic`（static）← EmueraConsole / Process / Session / JsonlProtocol 各自穿墙读取；测试无法隔离
- After：`SessionContext`（实例，持有 console/process/...）经构造注入；测试 `new SessionContext(fake)` 无需进程状态

### 候选 2 — Config 静态上帝类（144 个 public static 成员）

- **强度**：Strong
- **依赖类别**：local-substitutable
- **文件**：
  - [Shared/Runtime/Config/Config.cs](file:///d:/LaoBro/Emuera.MCP/Emuera.Headless/Shared/Runtime/Config/Config.cs)（659 行）
  - [Shared/Runtime/Config/ConfigData.cs](file:///d:/LaoBro/Emuera.MCP/Emuera.Headless/Shared/Runtime/Config/ConfigData.cs)（925 行）
  - [Shared/Runtime/Config/ConfigCode.cs](file:///d:/LaoBro/Emuera.MCP/Emuera.Headless/Shared/Runtime/Config/ConfigCode.cs)
  - [Shared/Runtime/Config/ConfigItem.cs](file:///d:/LaoBro/Emuera.MCP/Emuera.Headless/Shared/Runtime/Config/ConfigItem.cs)
  - [Shared/Runtime/Config/JSON/JSONConfig.cs](file:///d:/LaoBro/Emuera.MCP/Emuera.Headless/Shared/Runtime/Config/JSON/JSONConfig.cs)

**Problem**：`Config` 是 659 行纯静态类，**144 个 `public static` 成员**。全仓 `Config.FontName` / `Config.UseSaveFolder` 散落调用。删除测试：删掉 Config，144 处调用全部塌缩到调用方 — 复杂度集中，证明它在赚钱。但它的 interface 与 implementation 几乎同宽（每个 static 属性就是一行 delegation），是教科书级 shallow module。

**Solution**：ConfigData 升为实例（已存在 925 行数据类，只需去掉 static），加载 emuera.config 后作为依赖注入。FontFactory / Process / EmueraConsole 接收 ConfigData 而非读 static。

**Benefits**：
- **depth**：加载逻辑沉到实现，interface 只剩"取值"
- **locality**：配置解析 bug 集中到 ConfigData 一处
- **leverage**：一个 ConfigData 实例，N 个消费者，测试用 fake
- Shared 债务清零（P2-6）的前提：static 去掉后 nullable 警告才可逐条修

**依赖**：建议在候选 1 之后落地（共享实例注入机制）。

### 候选 3 — Process god object（3636 行，与 GlobalStatic 双向耦合）

- **强度**：Worth exploring
- **依赖类别**：in-process
- **文件**（5 个 partial，共 3636 行）：
  - [Process.cs](file:///d:/LaoBro/Emuera.MCP/Emuera.Headless/Shared/Runtime/Script/Process.cs)（603 行，主文件，~17 public 方法）
  - [Process.CalledFunction.cs](file:///d:/LaoBro/Emuera.MCP/Emuera.Headless/Shared/Runtime/Script/Process.CalledFunction.cs)（331 行）
  - [Process.ScriptProc.cs](file:///d:/LaoBro/Emuera.MCP/Emuera.Headless/Shared/Runtime/Script/Process.ScriptProc.cs)（972 行）
  - [Process.State.cs](file:///d:/LaoBro/Emuera.MCP/Emuera.Headless/Shared/Runtime/Script/Process.State.cs)（590 行）
  - [Process.SystemProc.cs](file:///d:/LaoBro/Emuera.MCP/Emuera.Headless/Shared/Runtime/Script/Process.SystemProc.cs)（1140 行）

**Problem**：ERB 引擎核心被塞进一个 partial 类：脚本执行、系统指令、状态管理、函数调用四职责混在 3636 行里。`Process.Initialize` 直接写 `GlobalStatic.GameBaseData` 等 9 字段 — 与候选 1 双向耦合。无法在测试里实例化 Process 而不拉起整个引擎。

**Solution**：沿 ERB 生命周期（加载 / 求值 / 指令派发 / 状态）切 seam。Process 收敛为派发入口，partial 各自升为深模块，依赖经 SessionContext 注入而非 GlobalStatic。

**Benefits**：
- **locality**：ERB 指令 bug 集中到 StatementDispatch，不再混在 1140 行 SystemProc
- **depth**：Evaluator 的 interface 远小于当前 Process 的 17+ public 方法

**风险**：最高 — 引擎核心，回归面大；需 ADR 护航。
**依赖**：候选 1（GlobalStatic 解除）先落地。

### 候选 4 — Web 前端接缝过浅（ops 是 displayLineList 的有损投影）

- **强度**：Strong
- **依赖类别**：ports & adapters
- **文件**：
  - [Agent/TurnRecord.cs](file:///d:/LaoBro/Emuera.MCP/Emuera.Headless/Agent/TurnRecord.cs)
  - [Server/KestrelGameServer.cs](file:///d:/LaoBro/Emuera.MCP/Emuera.Headless/Server/KestrelGameServer.cs)
  - [Terminal/TerminalRenderer.cs](file:///d:/LaoBro/Emuera.MCP/Emuera.Headless/Terminal/TerminalRenderer.cs)
  - [Agent/ButtonRegionTracker.cs](file:///d:/LaoBro/Emuera.MCP/Emuera.Headless/Agent/ButtonRegionTracker.cs)
  - [Shared/UI/Game/ConsoleDisplayLine.cs](file:///d:/LaoBro/Emuera.MCP/Emuera.Headless/Shared/UI/Game/ConsoleDisplayLine.cs)

**Problem**：CLI 的 `TerminalRenderer` 直接读 `displayLineList`（富：行/段/按钮/样式/坐标）；Web 只拿到 `TurnRecord.ops[]`（print/newline/clearline/clear/set_bg）。`ButtonRef` 只有 value 无几何，前端须重写 `ButtonRegionTracker`。无全屏路由，WS 晚加入者无回放。图像 `PrintImg` 退化为 `node.ToString()`。

**Solution**：收敛为单一 DisplayState module：全量快照路由（首次/重连）+ 增量 ops + 按钮几何 + 资源引用。CLI 与 Web 同为 adapter。

**Benefits**：
- **leverage**：一个接口，CLI/Web/测试三个 adapter
- **depth**：渲染状态全部藏在实现后，前端不再重写终端逻辑
- **interface 是测试面**：快照/增量可单测，无需真实游戏
- 两个 adapter（CLI + Web）证明 seam 真实存在

> ⚠ **ADR 冲突**：与 [ADR-0003](file:///d:/LaoBro/Emuera.MCP/docs/adr/0003-websocket-hub-bypass.md) 的 v1 范围部分冲突 — 该 ADR 接受"晚加入者不回放历史"。但 Web 前端若无初始全屏状态根本无法渲染，摩擦真实。建议重开 ADR-0003 评估"v1 快照路由"是否纳入。

## 六、词汇表

**架构词汇**（来自 `/codebase-design`）：
- **module** — 有 interface 与 implementation 的任意尺度单元
- **interface** — 调用方须知的全部事实（签名 + 不变量 + 错误模式 + 性能）
- **depth** — interface 的杠杆：行为量 / interface 学习成本
- **seam** — 无需就地修改即可改变行为的位置
- **adapter** — 在 seam 处满足 interface 的具体物
- **leverage** — 调用方从 depth 获得的能力杠杆
- **locality** — 维护者从 depth 获得的聚焦收益
- **删除测试** — 删掉 module 后复杂度消失 = pass-through；复杂度重现 = 在赚钱

**领域词汇**（来自 `CONTEXT.md`，节选）：
- **WaitInput** — 游戏等待输入状态（`ConsoleState.WaitInput`）
- **TINPUT** — 带超时的输入指令
- **TurnRecord** — 协议层回合记录（v2 含 `ops[]`）
- **displayLineList** — 控制台显示行富模型（行/段/按钮/样式/坐标）
- **Session** — 服务器单会话对象，持有 EmueraConsole + AgentJsonlProtocol + HttpSessionIO
- **GlobalStatic** — 进程级单会话全局状态（9 核心字段）
